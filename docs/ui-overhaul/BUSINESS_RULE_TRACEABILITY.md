## Traceability rules for implementation

1. A UI story must cite at least one rule ID and one authoritative endpoint/state machine.
2. A status label must map to a persisted or provider-observed state; unknown data is `unavailable`, not zero or pass.
3. A material action must show the server denial unchanged enough for the user to recover safely.
4. Any rule-changing PR updates this table, the relevant backend tests, and the screen-state tests together.
5. The missing BP v1.2/Roadmap v1.1 cannot be used as implicit authority. Reconcile and review them before changing these rules.

# Architecture quality attributes

**Current:** These scenarios translate the active architecture drivers into reviewable responses and measures for the source-controlled platform.

**Target:** Measures that require live provider, scheduler, backup, recovery, or deployment receipts remain target operational proof until retained evidence exists.

**Deployed:** No scenario in this document asserts a production deployment; deployed controls require an immutable provider-bound record.

**Verified:** A measure is verified only by the exact linked automated or retained operational evidence for its stated scope. Source/configuration rows are not live verification.

## Evidence interpretation

Use these evidence classes consistently:

| Class                         | What it can establish                                                                      | What it cannot establish alone                                 |
| ----------------------------- | ------------------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| Source/configuration          | A control or desired policy is present and reviewable.                                     | That it ran, is enabled, or matches a live provider.           |
| Automated test/fitness gate   | The named behavior passed in the tested model/environment.                                 | Exhaustive interleavings, human usability, or live operations. |
| Deployment verification       | An immutable candidate matched a named live deployment and probes at a recorded time.      | Continued health after the verification window.                |
| Operational receipt/rehearsal | A schedule, backup, restore, alert, provider, or recovery path produced retained evidence. | Another environment or a future run.                           |

## Trade-offs and review triggers

- Defence in depth adds database and request complexity, accepted for tenant isolation and material-release integrity.
- A single deployable reduces current operational cost, but inactive durable work must not be smuggled into request lifetime; measured pressure triggers a topology review.
- Fail-closed activation can reduce feature availability, accepted over unapproved external effects or invented authority.
- Generated contracts and catalogues add change ceremony, accepted for deterministic traceability; excessive hotspot exceptions trigger decomposition rather than permanent waivers.

Revisit these scenarios when a catalogue change trigger fires, a risk changes status, a measure becomes untestable, or live evidence contradicts the documented response.
